# 使用与排错

## 调整显示

游戏根目录双击 `MuseDash-Settings.cmd`，或直接打开 `UserData/MuseDashSteamPresence/MuseDashPresenceSettings.exe`。

**不需要先启动游戏。** 推荐先打开设置、保存，再从 Steam 启动游戏。设置软件不要求游戏或 Steam 正在运行，保存后可以直接关闭窗口。

以上适用于完整 ZIP 或已完成首次准备的 Hub 安装。Hub 最初只有主 DLL，因此先照常启动一次游戏来生成独立设置程序；默认显示可直接使用，其后修改设置不必再开游戏。根目录入口、非打歌自定义文字、曲名／作者开关和分隔符功能全部相同。

## 独立启用／停用和环境检查

本窗口独立操作，不需要开启其他模组管理器。先退出 Muse Dash，再点击“停用插件”，会同时停用主插件与早期组件；“启用插件”恢复两者，已保存的设置保留。游戏运行时按钮不可操作，因为不能靠改名热卸载运行中的插件。设置文字仍可在游戏中修改。

“获取 MelonLoader”打开官方安装器下载页，不会自动安装或覆盖加载器。界面区分缺失文件、缺少加载器、未验证版本和停用状态。文件检查通过后，另行显示“等待游戏”“等待插件回报”“状态已提交”或“本机缓存确认”，不把文件存在误报成已同步。

关闭设置窗口不等于停用插件。如果借助其他工具只关闭了主插件，新版早期组件在下次启动时也会停止独立上报菜单状态；想完整停用／恢复，仍建议使用本窗口按钮。

预览示例使用本体曲目“ものふぉびあ”与作者“とりぴよ feat. 凛々咲”，分隔符随选项变化。

默认：不打歌时 `Muse Dash`；打歌时 `Muse Dash : 曲名`，不显示作者。非打歌自定义文字和作者都默认关闭，可自行开启。

可分别开关曲名、歌曲作者。不打歌状态可以关闭或自定义，例如“休息中”“找谱中……”。分隔符支持无、一个空格、下划线、自定义文字；只有曲名和作者同时有内容时才加分隔符。

点击“保存并应用”后才保存实际设置：游戏未启动时，下次启动读取；游戏运行中，约 0.5–1 秒重新生成当前状态，不用重新开曲。关闭窗口不会停止游戏内插件。超长文字按 Steam 消息字节预算截短，不能无限长度显示。

“恢复默认”只更改窗口里的选项，需要再点保存。关闭有未保存修改的窗口时，会询问是否保存。

升级保留已有设置；想采用新默认值，点击“恢复默认”后保存即可，不会自动重置你的文字或其他偏好。

## 常见问题

### 设置窗口提示 Steam 版本尚未适配

这是版本保护主动停止发送，不是需要登录其他账号。查看 [兼容说明](COMPATIBILITY.md)，等待适配版或带上 DLL 哈希提交 Issue。不要删除哈希校验，也不要为了本插件降级 Steam。

### 完全没有曲名，仍只显示 Muse Dash

依次检查：

1. 压缩包是否完整解压到 `musedash.exe` 同级，而不是多套一层目录？
2. MelonLoader 日志是否加载 `Muse Dash Steam Song Presence` 和 `Muse Dash Steam Presence Early Start`？
3. 设置里是否把曲名、作者都关闭了？不打歌状态关闭时普通游戏名是正常结果。
4. `UserData/MuseDashSteamPresence/state` 最新 `.log` 是否有 `Steam build changed` 或 `Stopped`？
5. Steam 是否正在运行并登录？如果游戏更新导致加载器报错，先确认游戏和模组环境本身可运行。

### 曲名更新后，结算／选歌状态没有切换

确认已经重开游戏加载完整新版，两个插件都未停用。记录游戏、MelonLoader、Euterpe 版本，以及 `MelonLoader/Latest.log` 和本插件最新会话日志的相关片段。当前预发布仍需要完整生命周期实机回归。

### 自制曲作者缺失或不正确

读取的是 Euterpe 曲目元数据中的歌曲作者／艺人，元数据为空则不加作者和分隔符。谱面作者不等于歌曲作者。Euterpe 更新可能改变内部结构，不能保证未测试版本兼容。

### 长曲名被截短

同时显示歌曲名和作者时，可能超过文本长度或界面显示限制，导致信息显示不全；**目前尚无保证完整显示的解决方案**。插件会按 UTF-8 字节数安全截短，Steam 视图也可能只展示一部分。可关闭作者或缩短分隔符以减少截短，但不能保证所有曲目完整显示。

状态提交成功与本地缓存完整回读是不同步骤；日志中的 `sent-unconfirmed` 不一定代表好友看不到。本项目免费开源，欢迎提出显示改进、提交 Issue 或 PR。

### 换曲会反复弹“开始玩游戏”吗

**当前已验证客户端下，每次选歌、开曲、返回选歌只更新状态，不会反复触发“开始玩游戏”的新弹窗，不用担心打扰到好朋友们～** 依据包括同 AppID 更名的隔离通知逻辑测试和好友反馈，相同最终文字也不会重复发送。

这指状态切换引发的游戏启动通知；首次启动仍可能正常通知，Steam 聊天消息不受本插件控制。未来客户端改变行为时需要重新验证。

实际自己／好友视角的状态截图见[项目首页](../README.md#实际显示效果)。静态截图展示的是可见状态，不单独作为“没有弹窗”的证明。

## 日志和配置

- `settings.xml`：你的设置，首次保存生成。
- `settings.xml.bak`：上一份设置。
- `state/*.log`：插件自己的会话日志。
- `state/*.status`：最近发送／确认状态。
- `MelonLoader/Latest.log`：加载与游戏事件日志。

提交问题只需相关片段。日志可能包含曲名和本机路径；请先去除用户名、SteamID 或其他不愿公开的信息，不要上传整个 UserData、Steam 配置或崩溃转储。
